# PDF／Word 內容重排評估

2026-11-06。1.7.0 已實作「完整圖解＋可編輯正文」的重排第一階段；1.7.1 另外修正固定座標 Word 的[原頁保留](WORD-IMPORT.md)，不再直接送段落重排。以下保留完整方案與後續工作。**OCR、彩色卡片自動拆分、圖解節點與箭頭重建尚未提供**。

## 1.7.0 已實作

在 PDF 閱讀工具列開啟「圖文重排」。選擇來源頁、全文／上圖下文／左圖右文模板，調整圖解佔比，指定單欄或先左後右；文字先抽到可編輯輸入區，主題可人工確認。系統依字高差提出模板／標題候選，不能保證正確。

確認後把頁面加入佇列，可再處理其他頁、調整順序，另建一本圖文筆記。完整圖解裁切保留，正文使用現有文字分頁；放不下續頁，原 PDF／原註記不改動。圖解與接續說明也能建立為同一張考前小卡。

圖片經既有縮圖與媒體上限驗證。每次最多 50 頁。掃描頁沒有可讀文字時不假造內容，提示保留原貌或圖解；不自動 OCR。現在提供可校正的分區模板，尚未自動把五張底色卡片各自解構。

入口：`ReflowDialog.vue`、`core/reflow.ts`。Chrome／WebKit 以合成 PDF 驗證區域排除、文字校正、保留原 PDF、另建筆記、跨尺寸不溢出、建成含圖小卡與 ZIP 還原；使用者原始兩份 PDF 尚未取得。

## 原貌 PDF／Word 的基礎流程

- PDF：`core/pdf.ts` 保留原始 PDF 資產，逐原頁建立 `pdfPage` 區塊；`PdfPage.vue` 以 PDF.js 繪製 canvas，另外建立可選取／搜尋／註記的文字層。因此畫面是原頁繪製，原始檔並未被丟掉或只剩圖片，原貌模式仍不重建段落／圖解；重排模式另外抽取文字與裁切圖解，不改原頁。
- Word：`docx.worker.ts` 的 Mammoth 轉出語意 HTML，`normalize.ts` 建立標題、段落、清單、表格列與圖文區塊，`pagination.ts` 量測實際 DOM 高度並跨書頁分配。普通段落可以重新換行與分頁，使用頁白統一字級。這不代表保留或重建 Word 的背景卡片、浮動物件、繪圖群組、SmartArt 與複雜跨欄。
- 圖片內的文字：PDF 或 Word 都不能只靠調整 CSS 字級改變；放大整張圖片會一起放大圖解和文字。要獨立放大文字，需要原始文字／向量重建或 OCR 與版面辨識。
- 減少閱讀器留白會擴大內容容器，但原貌 PDF 仍按整頁比例縮放；遇到高度限制時，左右仍可能有空白，無法因此填補原頁自帶的空白。

## 使用者例子如何處理

### 無線區域網路：五塊底色卡片＋右欄小字

辨識五張卡片各自的邊界、標題與內容，存成可重排的群組；卡片內的時間軸、表格、連線圖依相依關係保留群組。把右欄說明還原為真正段落，套用統一可閱讀字級，再排成「卡片群組＋說明」或上下排列。不是依原始座標把所有文字串接，也不是任意打散圖上的箭頭及標籤。

### CSMA/CD：大圖解＋下方兩欄文字

先把外框內整張圖解視為不可拆的群組，依可用寬高等比放大。下方標題與兩欄說明還原成段落，合併正確閱讀順序，增加字級並向下延伸。若要把圖解內的字也獨立放大，就要重建圖形／節點與箭頭，或取得原始可編輯圖解；單純放大裁圖不能達到獨立改字。

只有截圖無法判定來源檔裡是文字、向量還是整張嵌入圖片；需以實際 PDF／DOCX 的物件與文字層確認。

## 建議的判定與排版流程

1. **解析來源 → 共用內容結構**：每個內容項保留類型、文字、樣式角色、原頁、座標、群組及閱讀順序；Word 優先使用既有語意，PDF 優先文字與結構樹，缺乏可靠文字時才走 OCR／版面模型。依每一頁／每個區塊判定，同一檔可混合多種內容。
2. **依內容選少量模板**：一般文字走流式段落；多張獨立卡片走卡片群組；大圖解＋說明走上下排列；表格保留儲存格結構；流程圖與關聯圖保持完整群組。不是替每張文件硬編一套版型，也不只看副檔名。
3. **可讀字級 → 實際量測 → 分頁**：先設定可讀字級，圖解依書頁可用寬高限制縮放，再量測內容高度；放不下就續到下一書頁。不能承諾所有字放大、全部內容不減少，且永遠保持原 PDF 一頁對一本書一頁。
4. **驗證與退回**：檢查文字遺漏、順序、表格、圖解群組及邊界；低信心內容保留原貌，讓使用者在預覽調整群組／順序，而不是默默丟字。原始 PDF 始終可切回查看。

建議分階段：先做可校正的區塊選取與「圖解＋可重排說明」，用真實範例驗證；再加入自動辨識卡片、欄位及 OCR。對外可呈現「原貌／重排」及簡單的區塊校正，不需把解析器名稱或內部信心分數塞進閱讀畫面。

## 接續時需要處理的工程工作

- 擴充目前 `Block`，加入群組、來源頁／座標、圖解區域與閱讀順序，保留舊 IndexedDB／ZIP 相容性。
- 保留原始檔與原貌閱讀，重排版另存結構，失敗可回復；不要直接覆寫使用者原筆記。
- 建立原貌／重排的定位對照；既有重點不能把原頁文字 offset 直接套到重排文字上。
- 本機 PDF.js 可取得文字與繪製資訊；一般化版面分析／OCR 需要額外模型或本機處理服務，不能假設現在純瀏覽器、純靜態部署已經能直接承載任意 Python 解析工具。
- 用合成測試與經使用者提供的範例驗證：繁體中文、多欄、色塊、表格、流程圖、掃描頁、混合頁；字不能消失、重複、亂序或超出書頁。
- 1.7.1 已取得使用者兩組 PDF／DOCX 並驗證固定版面 Word 的原頁保留；自動區塊拆解／OCR 尚未實作，不把原頁成功誤當智慧重排驗證，也不預先編造辨識成功率。

## 官方參考

- [PDF.js PDFPageProxy](https://mozilla.github.io/pdf.js/api/draft/module-pdfjsLib-PDFPageProxy.html)：`getTextContent`、`getOperatorList`、`getStructTree`（可能不存在）與原頁繪製。
- [Mammoth.js](https://github.com/mwilliamson/mammoth.js)：著重 Word 語意而非忠實複製樣式，複雜文件轉換有限制。
- [DoclingDocument](https://docling-project.github.io/docling/concepts/docling_document/)：文字、表格、圖片、群組、閱讀順序及來源座標可使用同一種文件結構表達；此處作架構參考，尚未安裝或整合。
